## 直觉：时间索引是第一公民

金融表如果只按「第几行」对齐，就很容易把**明天的价格**不小心接到今天的信号上。时间索引（`DatetimeIndex`）强迫你显式回答：这一行代表哪个交易日的哪一个字段？两个序列合并时，是按日期对齐，还是按位置硬拼？

**错位 = 隐性前瞻（lookahead）**：例如用「明日收盘」判断「今日该不该持仓」。回测曲线会变漂亮，但研究结论是假的。

## 公式

简单收益：

<Formula label="相邻收盘价的相对变化">
r_t = P_t / P_(t-1) − 1
</Formula>

长度为 w 的简单移动平均：

<Formula label="滚动均值">
MA_t(w) = (P_t + P_(t-1) + … + P_(t−w+1)) / w
</Formula>

## 手算小例子

取三天收盘 100, 101, 100.5：

- r_2 = 101/100 - 1 = 0.01
- r_3 = 100.5/101 - 1 ≈ -0.00495
- MA_3 在第三天：(100+101+100.5)/3 = 100.5

## Python 实验（已本地运行）

仓库脚本：`examples/p0/01_pandas_timeseries.py`（合成 OHLC，无网络）。

```python
import pandas as pd

idx = pd.bdate_range("2024-01-02", periods=8)
close = pd.Series(
    [100.0, 101.0, 100.5, 102.0, 101.5, 103.0, 104.0, 103.5],
    index=idx,
    name="close",
)
ohlc = pd.DataFrame({
    "open": close.shift(1).fillna(close.iloc[0]),
    "high": close + 0.5,
    "low": close - 0.5,
    "close": close,
})
ret = ohlc["close"].pct_change()
ma3 = ohlc["close"].rolling(3).mean()
good_signal = (ohlc["close"] > ma3).astype(int)
position = good_signal.shift(1)
bad_signal = (ohlc["close"].shift(-1) > ma3).astype(int)  # 故意用未来收盘
```

## 常见错误 / 陷阱

1. **`reindex` 后盲目 `ffill`**：把停牌空档填成「假成交价」，再算收益，等于发明了并不存在的报价。  
2. **按行号 `merge` 而不是按日期 `align`/`join`**：两个来源的日历不同时会静默错位。  
3. **行循环改价格却忘记时区/交易日历**：向量化 `pct_change`/`rolling` 更不易漏边界，但仍要检查 `NaN` 位置。  
4. **信号未 `shift` 就乘当日收益**：经典 lookahead。  
5. **不写断言**：dtype 变成 object、重复日期索引，错误会拖到很后面才爆。
