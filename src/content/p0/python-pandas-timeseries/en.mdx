## Intuition: the time index is first-class

If a finance table is aligned only by row number, it is easy to attach **tomorrow’s price** to today’s signal by accident. A `DatetimeIndex` forces an explicit answer: which session does this row belong to? When two series merge, do they align by calendar or by position?

**Misalignment = silent lookahead**: e.g. using tomorrow’s close to decide today’s position. Equity curves look better; the science is fake.

## Formulas

Simple return:

<Formula label="Relative change between adjacent closes">
r_t = P_t / P_(t-1) − 1
</Formula>

Simple moving average of window w:

<Formula label="Rolling mean">
MA_t(w) = (P_t + P_(t-1) + … + P_(t−w+1)) / w
</Formula>

## Worked numeric example

Closes 100, 101, 100.5:

- r_2 = 101/100 - 1 = 0.01
- r_3 = 100.5/101 - 1 ≈ -0.00495
- Third-day \(MA_3 = (100+101+100.5)/3 = 100.5\)

## Python lab (actually run locally)

Script: `examples/p0/01_pandas_timeseries.py` (synthetic OHLC, no network).

```python
import pandas as pd

idx = pd.bdate_range("2024-01-02", periods=8)
close = pd.Series(
    [100.0, 101.0, 100.5, 102.0, 101.5, 103.0, 104.0, 103.5],
    index=idx,
    name="close",
)
ohlc = pd.DataFrame({
    "open": close.shift(1).fillna(close.iloc[0]),
    "high": close + 0.5,
    "low": close - 0.5,
    "close": close,
})
ret = ohlc["close"].pct_change()
ma3 = ohlc["close"].rolling(3).mean()
good_signal = (ohlc["close"] > ma3).astype(int)
position = good_signal.shift(1)
bad_signal = (ohlc["close"].shift(-1) > ma3).astype(int)  # peek at future close
```

## Common mistakes / pitfalls

1. **Blind `ffill` after `reindex`** — invents quotes on halt days and pollutes returns.  
2. **Row-number merges** instead of calendar `align`/`join`.  
3. **Python row loops** that skip calendar edge cases; prefer vectorized ops, still inspect NaNs.  
4. **No `shift` on signals** before multiplying by same-bar returns.  
5. **No asserts** — object dtypes and duplicate dates fail late and loudly.
