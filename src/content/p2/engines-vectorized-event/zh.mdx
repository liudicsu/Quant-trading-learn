## 学习目标

本课（约 **8 学时**：概念 3h + 对照实验 4h + 文档 1h）实现一个**最小事件驱动引擎**，证明其净值与向量化次日开盘路径一致，演示向量化收盘路径难以干净表达的**止损**，并按**官方文档**对照各库。前置：`costs-in-backtest`。

**课内目标：** 实现事件/订单/成交/组合；断言事件净值匹配向量化；说明何时必须用事件引擎。

**必须教会：** 引擎选择=成交/日历假设；先诚实向量化再事件校验；止损/限价/多资产/资金约束需要事件；同构内核概念。

<Callout type="info" title="学习用途">
玩具 MA + 合成开盘价，不是生产 OMS 或实盘机器人。
</Callout>

## 参数

- MA=10；Rf=0；市价单在**下一根开盘**成交；匹配测试用 open=昨收  
- 止损演示：相对入场 **3%**；区间代理 = min(open, close)

## 向量化成交时点

同日收盘净值 ≈ **2.29**（偏乐观）。次日开盘 / `shift(1)` ≈ **0.818**。静默同日默认会抬高结果。

## 何时需要事件引擎

当成交取决于**日内路径**或**状态**时用事件：

- **止损 / 止盈 / 限价**（成交价 ≠ 收盘）  
- **多资产**错位成交 / 部分成交  
- **资金 / 保证金 / 风控**在发单前检查  

止损演示：stop_exits=**1**，含止损净值 ≈ **0.821** vs 无止损 **0.818**。单靠收盘到收盘的向量，若无日内规则就无法把成交钉在止损价。

## 常见错误 / 陷阱

1. 把库名当成假设说明书。  
2. 向量化同日默认。  
3. 声称纯收盘向量「有止损」却无日内规则。  
4. 在 handle_data 读未来 bar。  
5. 未对齐成交约定就横向比引擎。
