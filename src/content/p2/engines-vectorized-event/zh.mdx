## 学习目标

本课（约 **8 学时**：概念 3h + 对照实验 4h + 可选文档 1h）弄清引擎假设：向量化默认风险、两种成交时点净值、用 initialize/handle_data 描述事件循环。前置：`costs-in-backtest`。

**课内目标：** 陈述向量化默认风险；对比两成交时点净值；描述事件循环。

**必须教会：** 引擎选择 = 成交与日历假设；先诚实向量化再事件验证；同构引擎降低研究≠实盘缝隙（概念）。

<Callout type="info" title="学习用途">
不绑定单一商业产品；概念优先。
</Callout>

## 参数

- MA=10；gap_seed=4 生成带跳空的 open；Rf=0  

## 同信号，两成交时点

向量化同 bar 收盘净值可到 **~2.29**；次日开盘成交约 **0.82**；`shift(1)` 收盘约 **0.82**。默认若偷偷同 bar，会乐观。

## 事件循环素描

`initialize`：日历、费用、宇宙、热身。  
`handle_data(bar)`：只读 as-of 数据 → 发单 → 引擎在**后续事件**成交。

## 同构引擎概念（已读文档）

[NautilusTrader 架构文档](https://nautilustrader.io/docs/latest/concepts/architecture/)写明 Backtest / Sandbox / Live 共享同一 `NautilusKernel`——用同一套核心降低「研究代码 ≠ 实盘代码」的缝隙（概念层；本课不安装实盘）。

[RoundtableSpace 的引擎列表帖](https://x.com/RoundtableSpace/status/2111272232249143360)把 NautilusTrader 概括为「同一代码跑回测与实盘机器人」，并并列 Hummingbot / Jesse / vectorbt 等——当作**选型地图**，仍要自己写成交假设段。

## 常见错误 / 陷阱

1. 把库名当成假设说明书。  
2. 向量化默认同 bar。  
3. 事件驱动却在 handle 里读未来 bar。  
4. 不写假设段。  
5. 没成本就比较引擎。
