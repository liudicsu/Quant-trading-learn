## Parameters

- MA=10; gap_seed=4 for gappy opens; Rf=0  

## Same signal, two fill timings

Vectorized same-bar close NAV can hit **~2.29**; next-open fill ≈ **0.82**; `shift(1)` close ≈ **0.82**. Silent same-bar defaults are optimistic.

## Event-loop sketch

`initialize`: calendar, fees, universe, warm-up.  
`handle_data(bar)`: read as-of data only → emit orders → engine fills on a **later** event.

## Isomorphic engines (docs read)

[NautilusTrader architecture](https://nautilustrader.io/docs/latest/concepts/architecture/) states Backtest / Sandbox / Live share one `NautilusKernel` — same core path shrinks research≠live gaps (conceptual; this lesson does not install live trading).

[RoundtableSpace’s engine list post](https://x.com/RoundtableSpace/status/2111272232249143360) summarizes NautilusTrader as “the same code runs your backtest and your live bot,” alongside Hummingbot / Jesse / vectorbt — use it as a **map**, and still write your own assumptions paragraph.

## Common mistakes / pitfalls

1. Treating a library name as an assumptions sheet.  
2. Vectorized same-bar defaults.  
3. Reading future bars inside handle_data.  
4. No assumptions paragraph.  
5. Comparing engines without costs.
