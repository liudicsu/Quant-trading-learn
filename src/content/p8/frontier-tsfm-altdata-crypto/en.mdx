## TSFM finance eval (follow-up on P5)

## Crypto / on-chain: CCXT, funding, GMX, @sera00111

- **[CCXT](https://docs.ccxt.com/)** — unified CEX API surface (tickers, OHLCV, funding). Lab writes a **CCXT-shaped** funding CSV offline (`symbol`, `fundingRate`, `markPrice`, …) — structure reference only.
- **Funding carry (numeric):** $100k long perp, +1 bp per 8h → ≈ **−$30/day**, ≈ **$900 / 30d**, ≈ **1095 bps/year** if the rate never moves. Regime foil flips the sign — constant-rate ann. is a teaching foil, not a forecast.
- **[GMX fees docs](https://docs.gmx.io/docs/trading/fees/)** — dominant side pays minority; funding tied to OI imbalance; **funding accrues continuously** (per-second). Settlement on modify/close is mainly **borrow-fee / position-fee** mechanics (accrued funding is also applied then — do not overstate “settle on close” as the funding story). Lab prints a toy `savedFundingFactorPerSecond` from OI imbalance.
- **[OpenBB Open Data Platform](https://openbb.co/blog/openbb-releases-open-data-platform/)** — open-source **data aggregation** (“connect once, consume everywhere”: Python / REST / MCP). Name it as a PIT-friendly aggregation pattern; this course still uses offline mocks only. Nearby reporting tools in the same niche stack include **PyFolio** (portfolio tear sheets) and Alphalens (factor tear sheets).
- **[Trading Strategy GMX/CCXT adapters](https://tradingstrategy.ai/blog/gmx-adapter-for-ccxt)** — CCXT-compatible GMX interface (`eth_defi.gmx.ccxt`) plus FreqTrade middleware. Structure reference for on-chain adapters; no live keys here.
- **[@sera00111 tooling note](https://x.com/sera00111/status/2108332340753969191)** (P2-verified): minute/hour research can start from [Binance Vision](https://data.binance.vision/) + CCXT-style free entry; choose grain **after** you know the strategy.

## Common mistakes / pitfalls

- Zero-shot TSFM on noisy daily excess often loses to strong CS/tree baselines.
- Mock ≠ published Chronos/TimesFM checkpoints.
- **Crypto survivorship:** delisted perps/coins vanish from free histories.
- **Funding regime shifts** flip carry; bridges/MEV/oracle/liquidity risks sit outside CEX CCXT.
- Nautilus identical kernel ≠ identical latency, partial fills, or recon outcomes.
